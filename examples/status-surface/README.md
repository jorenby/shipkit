# status-surface — the minimal reference UI

A tiny, zero-dependency status surface for a Loop-Mode Ship. It renders the
loop's `state/status.json` and lets the Captain drop a steer from a browser —
phone or desktop.

This is the **minimal reference exemplar** plus a thin *working-with-projects*
layer (Watch 2, PROJECT-UI). The core remains the `status.json` contract + a
steer box; on top of it the page now has **Queue** and **Tickets** tabs that read
`queue.md` and `projects/*/tickets/*.md` (visibility-first), and a per-ticket
steer box. Every write still goes through the declared-envelope drop path — the
page never mutates ship state directly (the Mate owns queue/ticket writes).

Richer surfaces still to come (SSE live-update, a hot-list, push notifications,
gauges) remain **separate optional modules** layered on top.

It is also **mobile-friendly + an installable PWA** (Watch 3, UI-MOBILE-PWA):
responsive on a phone viewport (touch targets, safe-area insets, no horizontal
scroll), and installable to the home screen — `server.py` serves a manifest, a
service worker, and app icons. The service worker caches only the **app shell**
(html/css/icons/manifest) for offline-open; it **never** caches the live state
(`/status.json`, `/queue.json`, `/tickets.json`, `/ticket`) or any POST — those
always hit the network. Multiple browser tabs coexist (independent per-tab
polling; a `BroadcastChannel` nudges sibling tabs to refresh after a steer).

## PWA / mobile

- **Install:** open the surface over a secure context (`localhost` in dev, or an
  HTTPS origin like the Tailscale URL on a phone) and use the browser's *Add to
  Home Screen* / *Install* action. `display: standalone` opens it chrome-free.
- **Offline:** the shell opens offline from cache; live panels show
  "unavailable" until the network returns (live state is never cached).
- **Updating the shell:** bump `SHELL_CACHE_VERSION` in `server.py` when you
  change html/css/icons. The service worker drops the old cache on activate.
- **Icons** were generated by `_make_icons.py` (stdlib only, no PIL) — a solid
  accent-blue plate with a white anchor glyph. Re-run it to regenerate.
- **Behind a reverse proxy:** the server still binds `127.0.0.1` only; a proxy
  (e.g. `tailscale serve`) forwarding to `127.0.0.1:8000` provides the HTTPS
  secure context the PWA install + service worker require. Note `POST /steer`
  remains **unauthenticated** — keep the proxy tailnet-only (not public Funnel).

## Run

```sh
python3 server.py
```

Then open <http://localhost:8000>. No `npm`, no `pip`, no build step —
Python 3 stdlib only, cross-platform.

By default it reads/writes the shipkit checkout this file lives in
(`../../state/status.json` and `../../inbox/drops/`). Override with env vars
if your ship lives elsewhere:

```sh
SHIP_ROOT=/path/to/ship PORT=8080 python3 server.py
```

## The tabs

- **Status** — the original surface: `now`, tick, next wake, validator, last
  actions, and the global steer box (unchanged).
- **Queue** — renders `queue.md` by section (Ready / Active / Waiting / Blocked /
  On Hold / Done) with per-section counts. Linked items are clickable and jump to
  the ticket detail.
- **Tickets** — a filterable list of every `projects/*/tickets/*.md` (id, project,
  status badge, goal). Click one for a detail view with the full raw markdown and
  a **Steer this ticket** box.

## What it shows

- **Now** — `now.doing`, how long ago `now.since` was, and the `now.wake` reason.
- **Tick** — the monotonic loop counter.
- **Next wake** — when/why the loop next plans to wake.
- **Validator** — the loop's self-check state (green when `CLEAN`).
- **Last actions** — the most recent `last_actions[]`.

The page polls `GET /status.json` every 5 seconds. If a field is absent (a
headless loop writes only the core fields), it simply isn't shown.

## The steer box

Typing a steer and pressing **Send** issues `POST /steer`, which writes a
well-formed drop into `inbox/drops/` carrying the declared input envelope
(`shipkit_input: v1`, `source: status-surface`, `kind: steer`,
`wake_class: wake`). Because `wake_class` is declared, `classify_input.py`
reads it verbatim (no heuristic guessing) and the drop rides the normal
`classify_input → wake` path, so the loop wakes and responds to it the same way
it would any Captain steer — no special casing.

## Endpoints

| Method | Path            | Does                                                       |
|--------|-----------------|------------------------------------------------------------|
| `GET`  | `/`             | serves `index.html`                                        |
| `GET`  | `/status.json`  | returns the loop's `state/status.json` (read fresh)        |
| `GET`  | `/queue.json`   | parsed `queue.md` → `{sections: {Ready: [...], …}}`        |
| `GET`  | `/tickets.json` | `{tickets: [{id, title, status, goal, project, file}, …]}` |
| `GET`  | `/ticket?id=ID` | one ticket: parsed fields + raw `body` markdown            |
| `POST` | `/steer`        | writes a `type: steer` drop into `inbox/drops/`            |
| `POST` | `/steer-ticket` | same envelope, targeting a ticket (`ticket` id in body)    |
| `GET`  | `/manifest.webmanifest` | the PWA web app manifest (name/icons/theme)       |
| `GET`  | `/sw.js`        | the service worker (caches the app shell only)             |
| `GET`  | `/icon-*.png`   | app icons (192, 512, 512-maskable) for install/home-screen |

The four read endpoints are **pure visibility** — they never write. `/steer-ticket`
reuses the exact `/steer` envelope (`shipkit_input: v1`, `source: status-surface`,
`kind: steer`, `wake_class: wake`) and adds a `ticket:` field + a body line naming
the target, so it rides the same `classify_input → wake` path.

## The contract it renders

The surface reads only the **core** `status.json` fields, so it works against a
headless seed:

```jsonc
{
  "tick": 0,
  "wake_reason": "captain-launch",
  "now":  { "doing": "...", "since": "<ISO>", "wake": "..." },
  "next_wake": "HH:MM <tz> (reason)",
  "last_actions": ["..."],
  "validator": "CLEAN ✅"   // optional — omitted if no validator module
}
```

Rich fields a preset might add (`hot_list`, `ready_for_you`, `crew[]`, …) are
ignored here by design.
